# 2027 한울타리 FC 유니폼 투표

후보를 늘어놓고 **마음에 드는 것을 골라 담는다.** 고른 순서가 곧 순위다.

> 대진표(이상형 월드컵)는 걷어냈다 (총무 확인 2026-10-09).
> 붙는 상대에 따라 결과가 흔들려서 **디자인끼리 공정하게 비교가 안 됐다.**
> 1라운드에서 센 디자인끼리 만나면 둘 중 하나는 거기서 끝난다.

## 점수

| 순위 | 점수 (PICKS=3) |
|---|---|
| 1순위 | 3점 |
| 2순위 | 2점 |
| 3순위 | 1점 |

전원 합산해서 점수 → 1순위 표 수로 정렬한다.

## 두 번에 나눠 한다

1. **1차** — 17종에서 3개. 상위 5종이 결선 후보가 된다.
2. **결선** — 환경변수에 `SHORTLIST`(후보 id, 쉼표 구분)와 `PICKS=1`을 넣으면
   **같은 주소가 결선 투표로 바뀐다.** 집계 화면이 복사할 id를 찍어준다.
   표를 비우려면 `POST /api/reset?key=<ADMIN_KEY>&confirm=yes`.

## 폴더

```
kits.js            후보 17종 · 대진표 · 점수표   ← 여기만 고치면 된다
server.js          API + 정적 서빙
public/            index.html · app.js · style.css · results.html · kits/*.jpg
ROSTER.txt         명부 이름 (환경변수에 넣을 값, 저장소에 올리지 않는다)
```

## 환경변수

| 이름 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | ○ | Postgres 연결 문자열. 없으면 메모리에만 남고 재시작 시 사라진다 |
| `ADMIN_KEY` | ○ | 관리자 화면 열쇠(긴 문자열). API로 직접 부를 때 쓴다 |
| `ADMIN_PIN` | | 총무가 폰에서 넣는 짧은 비밀번호. 7번 틀리면 15분 잠긴다 |
| `ROSTER` | △ | 쉼표로 구분한 회원 이름. 투표 화면에서 **목록으로 고른다** |
| `ROSTER_LABELS` | | 화면에 쓸 이름을 따로 줄 때. `최지훈S=최지훈 (S),최지훈B=최지훈 (B)` |
| `VOTE_OPEN` | | `false`로 두면 투표 마감 |
| `DEADLINE` | | 마감 시각 기본값. 기본 `2026-10-25T00:00:00+09:00`. 관리자 화면에서 바꾸면 DB 값이 이긴다 |
| `PICKS` | | 한 사람이 고르는 개수. 기본 3. 결선에서는 1 |
| `SHORTLIST` | | 결선 후보 id(쉼표). 넣으면 그 후보만 나오고 화면이 「결선 투표」가 된다 |
| `ROUND_NAME` | | 화면 맨 위 문구. 안 넣으면 1차는 「2027 시즌」, 결선은 「결선 투표」 |
| `AUTH` `AUTH_SALT` | △ | 본인 확인(전화 뒷 4자리). `scripts/make_auth.py`가 만든 `AUTH.txt`에서 복사 |

**`ROSTER`는 코드에 넣지 않는다.** 저장소가 공개돼도 명부가 따라 나가지 않게 하기 위해서다.
값은 `ROSTER.txt`에 있다. **이 파일은 git에 올리지 않는다** (`.gitignore`에 있다).

> 동명이인 주의 — 이름이 투표자 식별자다. 같은 이름이 둘이면 뒤에 투표한 사람이
> 앞사람을 덮어쓴다. 동명이인이 있으면 `홍길동A` / `홍길동B`처럼 갈라서 `ROSTER`에 넣는다.
>
> 이름은 **치는 게 아니라 목록에서 고른다.** 쳐서 넣게 하면 동명이인이 자기 이름을
> 그대로 쳤다가 "명부에 없는 이름"으로 거부당한다. 50여 명이면 고르는 쪽이 빠르다.
>
> 구분자(`S`/`B`, `(S)`/`(B)`)는 **명부용이지 옷에 박을 글자가 아니다.**
> 유니폼 마킹에는 구분자를 뗀 본명이 찍힌다.

### 남은 설정 한 가지 — `DATABASE_URL`

DB 비밀번호는 API로 안 나와서 **직접 한 번 넣어야 한다.**
넣기 전까지는 투표가 막혀 있다 (표를 조용히 잃는 것보다 낫다).

1. DB 대시보드 → **Internal Database URL** 복사
2. 서비스 대시보드 → Environment → Add Environment Variable
   - Key `DATABASE_URL` / Value 붙여넣기
3. 저장하면 자동으로 다시 뜬다. 1~2분 뒤 투표 링크를 열어 시작 버튼이 눌리면 완료.

## 가격은 보여주지 않는다

가격이 보이면 디자인이 아니라 가격으로 고르게 된다 (총무 확인 2026-10-09).
화면에서 숨기는 게 아니라 **`/api/config`에서 아예 빼서** 페이지 소스에도 남지 않는다.
업체명도 같은 이유로 빼두었다. 집계 화면(총무용)에는 그대로 나온다.

## 마감 시각

관리자 화면에서 바꾼다. **DB에 저장되므로 재배포가 필요 없고 바로 적용된다.**
환경변수 `DEADLINE`은 DB에 값이 없을 때만 쓰인다.

- 메인 화면에 **남은 시간이 1초마다** 줄어든다
- 지나면 투표가 **자동으로 닫힌다**. 서버도 막고, 화면에도 「마감되었습니다」가 뜬다
- 한국 시간으로 적는다. Render 서버는 UTC로 돌기 때문에 오프셋(`+09:00`)이 붙어야 한다

## 본인 확인

다른 사람 이름을 골라 투표하는 걸 막는다. **전화번호 뒷 4자리**를 묻는다.

**연락처 원본은 서버에 없다.** `scripts/make_auth.py`가 뒷 4자리를 소금과 함께
해시해서 그 결과만 만든다. 서버는 대조만 할 수 있고 번호를 복원하지 못한다.
규정집의 「개인정보 반출 금지」를 지키면서 확인만 하기 위한 방식이다.

```
uv run --python 3.12 python scripts/make_auth.py     # → vote/AUTH.txt
```

`AUTH.txt`의 `AUTH_SALT`, `AUTH` 두 값을 Render 환경변수에 넣는다.
**이 파일은 git에 올라가지 않는다.**

**틀렸다고 막지 않는다** (총무 확인 2026-10-09). 제출할 때 한 번 되물어 오타를 잡아주고,
그래도 다르면 **그대로 받고 번호만 적어 둔다.** 집계 화면이 그 명단을 따로 보여준다.

- **맞는 번호는 저장하지 않는다.** 틀린 것만 남긴다 — 총무가 확인해야 하는 건 그것뿐이고,
  맞는 번호를 DB에 쌓으면 해시로 감춘 의미가 없어진다.
- 되묻는 것 자체가 「맞다/틀리다」를 알려주는 창구다. **5번 되물으면 그만 묻고 그냥 받는다.**
  안 그러면 1만 번 넣어보고 남의 번호 뒷자리를 알아낼 수 있다. (10분 뒤 다시 열린다 —
  시간을 들이면 뚫리므로, 작정한 공격을 막는 장치는 아니다.)
- 연락처가 없는 회원은 확인할 방법이 없어 **아무 4자리나 통과한다.**
  `make_auth.py`가 그 명단을 찍어준다. 번호를 받아 `members.csv`에 채우고
  다시 돌리면 막힌다.
- 소금을 바꾸면 해시를 전부 다시 만들어야 한다.

# 자체전 포메이션 보드 (`/board.html`)

같은 서버·같은 DB·같은 명부를 쓴다. 투표와 따로 돌아서, 보드가 죽어도 투표는 계속 받는다.

**https://hanultari-vote.onrender.com/board.html** — 보기는 링크만 있으면 누구나, 짜는 건 감독만, 전부 만지는 건 총무.

## 하루 일정 (총무 확정 2026-10-16)

| 때 | 누가 | 무엇을 |
|---|---|---|
| **토요일 하루** | 회원 | 유니폼 투표 → 끝 화면의 「내 포지션도 알려주기」 → 포지션 1~3개. 투표에서 넣은 이름·번호가 그대로 넘어와 한 번에 끝난다 |
| (준비) | 총무 | 보드 하단 **총무** → 감독 두 명 지정, 포지션 입력 기간 설정 |
| **일요일 경기** | 두 감독 | **감독 모드**(이름 + 전화 뒷 4자리)로 들어와 **한 명씩 번갈아** 고른다 → 모두 고르면 각자 **최종 확정** |
| 그 뒤 | 각 팀 감독 | ③ 포메이션 — 전술을 고르고 **말을 어디로든 끌어** 배치. 누구나 읽기 전용으로 본다 |

활동 회원 아이콘은 밝게(주 포지션 색), **휴면은 어둡게**. 휴면은 선택 대상이 아니다.

## 번갈아 고르기 + 연령대 비율

1. 선공은 추첨 (총무가 시작할 때 팀을 지정할 수도 있다). 그다음부터 A·B·A·B… 한 명씩.
2. **연령대 비율을 맞춘다.** 활동 회원 전체(두 감독 포함)의 연령대 인원을 두 팀이 똑같이 나눈다.
   한 팀이 한 연령대에서 가져갈 수 있는 인원은 그 연령대 **활동 회원의 절반(홀수면 올림)** 까지.
3. **팀 인원도 맞춘다.** 홀수 연령대의 「한 명 더」는 한 팀이 가져갈 수 있는 곳이 홀수 연령대 수의 절반(올림)까지.
   이게 없으면 건너뛰기가 생겼을 때 팀 인원이 2명 이상 벌어진다 (테스트로 확인된 문제).
4. 고를 수 있는 선수가 없는 쪽은 차례를 건너뛴다. 고른 선수는 **상대가 고르기 전이면** 되돌릴 수 있다.
5. 다 고르면 `review` — 두 감독이 각각 최종 확정하면 `done`(잠김). 총무는 한 단계씩 되돌릴 수 있다.

활동 39명(10대 3·20대 9·30대 11·40대 5·50대 9·60대 1·미상 1)을 임의 순서로 200번 끝까지 돌려도
연령대별 차이 1명 이하, 팀 인원 차이 1명 이하, 막다른 길 없음 (`npm test`).

규칙은 전부 `draft.js`에 있다 (입출력 없이 상태만 바꾼다). 연령대 맞춤은 총무 화면에서 끌 수 있다.

## 누가 무엇을 보나

- **누구나**: 포지션·팀·포메이션·진행 기록. **연령대는 공개 응답에 없다.**
- **감독(감독 모드)**: 위 + 남은 선수의 연령대, 두 팀의 연령대 표, 막힌 선수와 이유. 서버가 감독 본인 확인 뒤에만 내려준다.
- **총무(`ADMIN_KEY` / `ADMIN_PIN`)**: 전부. 어느 팀이든 대신 선택·되돌리기·확정·포메이션, 팀원 제외, 휴면↔활동 전환,
  입력 기간·감독·선공·연령대 맞춤 설정, 투표 집계(`/results.html`) 링크. 투표 집계 화면에서 넣은 비밀번호가 같은 탭에서 그대로 쓰인다.

## 포지션 입력 기간

총무 시트에서 시작·마감 시각을 정한다 (「토요일 하루로」 버튼 = 다가오는 토요일 00:00~24:00). 기간 밖에는 회원이 못 넣고, **총무는 언제든** 넣을 수 있다.
비우면 항상 열려 있다. 전화 뒷 4자리는 투표와 같은 방식 — 틀려도 한 번 되묻고, 그래도 다르면 받고 표시만 남긴다(총무 화면에서 확인).

## 환경변수 (추가 2개)

| 이름 | 필수 | 설명 |
|---|---|---|
| `DORMANT` | ○ | 휴면 회원 이름(쉼표 구분, `ROSTER`와 같은 표기) |
| `AGE` | ○ | `이름:30대,이름:40대,…` — **연령대 구간만**. 생년·연락처는 들어 있지 않다. 없으면 연령대 맞춤이 꺼진다 |

두 값은 총무 폴더에서 한 번에 만든다. **vote/ 에 git에 안 올라가는 `DORMANT.txt`, `AGE.txt` 가 생긴다.**

```bash
cd ..   # Chongmu
uv run --python 3.12 python scripts/make_board_env.py
```

각 파일의 한 줄을 Render 환경변수 `DORMANT`, `AGE` 에 넣는다. 연령대는 팀을 나누기 위해 서버가 알아야 하는 값이라 Render에 올라간다
(`ROSTER`·`AUTH`와 같은 위치). 개인정보 원칙상 구간 라벨 이상은 올리지 않는다.
`AUTH`·`AUTH_SALT`·`ROSTER`·`ROSTER_LABELS`·`ADMIN_KEY`는 투표와 같은 값을 그대로 쓴다.

  연락처가 없는 감독은 확인할 수 없으니 총무가 대신 한다.
- 감독 모드는 이름+번호를 요청마다 서버가 다시 확인한다 (세션 토큰 없음, 탭을 닫으면 사라진다).

## 저장

| 테이블 | 내용 |
|---|---|
| `board_positions` | 회원별 포지션 (이름이 키) |
| `board_state` | 팀 구성·포메이션 한 줄 (JSON). 쓸 때 서버 안에서 줄을 세우고 DB 행을 잠근다 |

`DATABASE_URL`이 없으면 메모리에 담는다 (로컬 확인용). 테이블은 첫 접속에 알아서 만든다.
**총무 → 처음으로 되돌리기**는 팀 구성과 포메이션만 지우고, 회원이 입력한 포지션·감독 지정·입력 기간은 남긴다.

# 유니폼 번호 · 사이즈 (회원 페이지의 「번호·사이즈」 탭)

**유니폼 투표가 끝난 뒤의 일이다** (2026-10-26). 투표 탭은 「종료」로 눌리지 않고, 새 탭에서 회원마다
등번호와 사이즈를 받는다. 탭 맨 위에 **투표 1위 유니폼**이 큰 사진으로 나온다.

> 투표가 닫혔는지는 기존 설정을 그대로 따른다 — `VOTE_OPEN=false`이거나 마감 시각이 지나면 닫힌 것이다.
> 배포한 서버에서 아직 열려 있다면 Render 환경변수 `VOTE_OPEN`을 `false`로 바꾸고, 관리자 화면의 마감 시각도 확인한다.
> (닫히기 전에는 투표 탭이 눌리고, 1위 유니폼은 보이지 않는다.)

## 번호 규칙

- **0~99**는 표에서 누르고, **세 자리(100~999)**는 입력한다. 한 사람에 번호 하나.
- **활동 회원은 기존 번호를 그대로 지킨다.** 기존 번호는 본인이 바꾸기 전까지 잠겨 있어서 다른 활동 회원은 못 고른다.
- **휴면 회원의 번호는 노란 점선**으로 보이고 **가져갈 수 있다.** 활동 회원이 가져가면 휴면 회원 쪽에서 빠진다
  (그 사실은 남아서 본인이 들어오면 알려준다). 휴면 회원도 번호를 적을 수는 있지만 보호되지 않는다.
- 활동 회원이 번호를 바꾸거나 놓으면 비는 번호가 **곧바로** 모두의 화면에서 선택 가능으로 바뀐다.
  번호의 상태(잠김·휴면·빔)는 저장하지 않고 회원들의 선택에서 매번 계산한다 (`numbers.js`).
- 활동 회원의 기존 번호끼리 겹쳤다면 둘 다 그 번호를 쥔 채로 두고 **먼저 확정하는 사람이 가져간다.**
  나머지는 새 번호를 골라야 한다. 활동·휴면이 겹쳤다면 활동 회원이 이긴다.
- 총무가 보드에서 **활동↔휴면**을 바꾸면 번호의 잠김 표시도 따라 바뀐다.
- **끝낸 사람** = 번호가 정해졌고 사이즈를 골랐다. 기존 번호를 그대로 쥔 활동 회원은 사이즈만 고르면 끝이다.
  총무가 미리 넣은 **기존 사이즈는 끝으로 세지 않는다** — 화면에 점선으로 미리 골라져 있고, 본인이 「맞아요」를 누르거나
  다른 사이즈를 골라야 끝난다 (옛 시트의 사이즈가 이번 옷에도 맞는지는 본인만 안다).

## 실시간

서버가 번호가 바뀔 때마다 접속 중인 사람에게 스냅샷을 밀어준다 (SSE, `GET /api/uniform/stream`).
탭을 열어 둔 동안만 연결하고 떠나면 끊는다. 바뀐 칸은 잠깐 반짝인다. 연결이 끊기면 브라우저가 다시 붙고,
못 붙는 동안은 15초마다 직접 불러온다. 같은 번호를 동시에 눌러도 저장소에서 줄을 세워(행 잠금) 한 사람만 가져간다.

## 누가 무엇을 보나

- **누구나**: 번호가 누구 것인지, 끝낸 사람 수. **사이즈는 공개 응답에 없다.**
- **회원 본인**: 내 번호·사이즈. 전화 뒷 4자리를 확인한다 — 투표와 달리 **틀리면 막는다** (번호는 남의 자리를 바꾸기 때문. 5번 틀리면 10분 잠김).
  본인 확인 없이 들어온 경우(「그냥 들어가기」)는 보기만 된다. 연락처가 없는 회원은 확인할 수 없어 아무 4자리나 통과한다(총무 표에 따로 나온다).
- **총무(`ADMIN_KEY` / `ADMIN_PIN`)**: 관리자 화면의 **번호·사이즈** 탭 —
  사이즈별 인원, 전체 표, **CSV 내려받기 / 표 복사**, **접수 마감**(마감하면 회원은 못 바꾸고 총무만 바꾼다),
  확정 유니폼 직접 지정, **기존 번호 가져오기**, 변경 기록. 회원을 누르면 그 회원 화면이 열려 대신 고칠 수 있다.

## 기존 번호 넣기

기존 번호는 **저장소에 없다** (명부와 같은 이유 — 공개 저장소). 둘 중 하나로 넣는다.

1. **총무 화면** → 번호·사이즈 → 「기존 번호 가져오기」에 한 줄에 한 명씩 `이름 번호`로 붙여넣는다.
   이름은 명부 표기(`최지훈S`)나 화면에 보이는 이름(`최지훈 (동생)`) 둘 다 된다. 번호 자리에 `-`를 쓰면 기존 번호를 지운다.
   겹치는 번호와 못 알아본 줄은 결과에 바로 알려준다. 이미 번호를 직접 고른 회원은 건드리지 않는다. DB에 저장되므로 재배포가 필요 없다.
2. 환경변수 `NUMBERS` (`이름:번호,이름:번호,...`). 총무가 화면에서 넣은 값이 이쪽보다 앞선다.

## 기존 사이즈 넣기

**총무 화면** → 번호·사이즈 → 「기존 사이즈 가져오기」에 한 줄에 한 명씩 `이름 사이즈`로 붙여넣는다 (예: `홍길동 XXL`).

- 시트 표기 `XXL`·`XXXL`·`XXXXL`은 `2XL`·`3XL`·`4XL`로 바꿔 받는다. 대소문자·공백은 가리지 않는다. 사이즈 자리에 `-`를 쓰면 기존 사이즈를 지운다.
- 목록(`SIZES`)에 없는 값이나 명부에 없는 이름은 「건너뛴 줄」로 이유와 함께 알려준다.
- 넣은 사이즈는 **제안**이다. 회원 화면에 점선으로 미리 골라져 있고 「이전 시트의 사이즈 ○○로 미리 채워 두었습니다」가 나온다.
  본인이 「맞아요」(또는 그 칩)를 누르면 확인, 다른 것을 누르면 변경이다. 확인하기 전에는 「끝낸 사람」에 세지 않는다.
- 이미 본인이 사이즈를 정한 회원의 값은 건드리지 않는다. 본인이 사이즈를 지워도 기존 사이즈가 되살아나지 않는다.
- 총무 표에는 확인 전인 기존 사이즈가 외곽선 칩(`L 기존`)으로, 확인된 것은 검은 칩으로 나온다. 사이즈별 인원에는 둘 다 센다.
  CSV의 「상태」 열에는 확인 전인 사람이 `사이즈 확인 전`으로 나온다. DB에 저장되므로 재배포가 필요 없다.

## 환경변수 (추가 2개)

| 이름 | 필수 | 설명 |
|---|---|---|
| `NUMBERS` | | 기존 번호 `이름:7,이름:10,…` (`ROSTER`와 같은 표기). 총무 화면에서 넣어도 된다 |
| `SIZES` | | 사이즈 목록(쉼표 구분). 기본 `XS,S,M,L,XL,2XL,3XL,4XL` |

## 1위 유니폼

투표가 닫힌 뒤에는 집계 1위(점수 → 1순위 표 수 → 이름순)가 자동으로 나온다. 결선(`SHORTLIST`)을 돌렸다면 결선 표만 센다.
다르게 정했다면 총무 화면에서 직접 고른다. 가격·업체명은 싣지 않는다.
